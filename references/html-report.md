# HTML 报告格式

当用户未指定其他格式时，评估结果必须生成一个可独立打开的 UTF-8 单文件 HTML，并在回复中提供文件链接。HTML 不依赖外部 CDN、字体、脚本或图片；样式和 SVG 图表全部内嵌。

## 输入结构

`scripts/render_html_report.py --input <json> --output <html>` 接收以下字段：

- `company`：`name`、`code`、`industry`、`latest_period`、`source`、`updated_at`。
- `periods`：三个评分期间，顺序固定为20%/30%/50%；每期包含 `label` 和五项 `metrics`。指标键为 `roic`、`growth`、`ccr`、`fcf_ic`、`debt_ebitda`，每项包含 `value`，可选 `display`、`status`、`score_override`。
- `trend`：最多六个观察期；每个对象包含 `label` 及上述五个指标的数值。缺失值使用 `null`。
- `conclusion`：结论段落数组。每一项须遵循“简洁的一句话观点＋数据或趋势描述”的结构；可使用“观点：描述”字符串，也可使用包含 `point`、`description` 的对象。
- `methodology_notes`：口径与限制数组。
  - 净负债口径必须明确披露：可自由使用货币资金是否扣除了受限资金、交易性金融资产的期末金额，以及是否存在受限或重复计算。

报告生成器会调用同目录评分器，禁止在渲染器中复制或修改评分规则。

## 固定报告结构

1. 顶部企业信息、最终得分、等级和数据状态。
2. 三期评分与时间加权追溯表。
3. 最新期指标评分明细表。
4. 三期综合得分柱状图。
5. 最新期五项标准分雷达图，五个轴统一使用0—100标准分。
6. 最新期加权贡献横向柱状图，以总分百分点展示各指标贡献。
7. 五年趋势数据表位于图表上方；其后为五项指标趋势小多图，曲线采用平滑贝塞尔线，完整年度和最新TTM使用不同点形或颜色，并以较大字号显示数值标签。
8. 评价结论、计算口径与“非投资建议”声明。

## 可视化规则

- 分数统一使用0—100坐标，避免视觉夸大。
- 原始指标各自使用独立趋势坐标，不把不同单位画在同一纵轴。
- 负数、零值、缺失值和待复核状态必须可辨识；缺失处不连线。
- 图表之外保留完整数据表，保证打印、无障碍阅读和结果复核。
- A/B/C/D/E使用一致的等级颜色，但颜色不能成为唯一的信息编码。
- 打印样式应避免卡片或图表被跨页截断。
- 不设置单独的“评分可视化”模块：“三个评价期间综合得分”置于“综合评分追溯”表格下方，并在三个期间得分条下增加按期间用不同颜色区分的“最终贡献构成”堆叠柱；“最新期加权贡献”和“最新期五项标准分雷达图”置于“最新期指标明细”表格下方并采用左右布局，其中加权贡献图获得稍宽的横向空间；宽度低于620px时改为单列。
- 五项趋势图固定为单列布局，每个指标独占一行并使用横向画布；不得因宽屏改成多列。
- 数据表在窄屏保持可读列宽并允许容器内横向滚动。




## 视觉风格

- 采用苹果产品页面式的克制视觉语言：深色高对比主视觉、充足留白、黑白灰主色、少量蓝色强调、白色内容卡片与轻量阴影。
- 不复制苹果商标、产品图、文案或具体页面；仅借鉴排版层级、留白与材质感。
- 减少传统仪表盘式粗边框和多层嵌套；标题尺度服务于报告而非广告，使用系统字体栈并保证移动端与打印可读性。



- 标题主视觉中企业信息位于左侧，最终得分固定右对齐展示；即使手机端换行，得分仍保持右对齐。



- 标题主视觉底部使用四列信息：行业、最新报告期、数据源、更新日期；标签在上、内容在下。总分放大并位于右侧视觉中心。



- 标题区总分只显示数值，不附加 /100；四项元数据使用严格等宽四列、统一内边距和分隔线。


- 标题区评分在右侧适度左移；元信息依次排列为行业、数据源、最新报告期、更新于，数据源列采用非对称内边距以避免与相邻字段交叉。
